# 교차 방식

## 역할

교차는 서로 다른 강한 규칙의 장점을 결합해 더 재사용 가능한 규칙을 만드는 방식이다.

## 강제 전제

교차는 매 세대 수행하는 필수 단계다.
[[세대-후보-생성]]의 후보 생성 의무를 충족한 뒤 평가기준에 가장 잘 맞는 상위 2개를 섞어 실질 개선의 중심 방향으로 삼는다.

## 적용 조건

상위 후보 2개를 섞을 때는 다음 조건을 지킨다.

- 두 규칙이 같은 실패를 다른 방식으로 줄인다.
- 결합 후 규칙이 더 짧거나 더 실행 가능해지며, 주인공 선택, 선택의 대가가 시험할 것, 다음 행동 압력의 연결이 더 선명해진다.
- 결합이 일반 창작론으로 흐르지 않는다.
- 결합 후에도 한 파일 한 역할 원칙이 유지된다.

## 교차 방법

- 상위 후보 2개의 공통 목적과 서로 다른 강점을 먼저 분리한다.
- 한 후보가 표면 증상을 줄이고 다른 후보가 더 이른 원인을 고치면, 더 이른 원인을 고치는 쪽을 중심으로 결합한다.
- 한 규칙의 입력 추출 방식을 다른 규칙의 생성 판단에 연결한다.
- 한 규칙의 평가 관점을 다른 규칙의 실패 방지 조건으로 옮긴다.
- 중복된 규칙 둘을 하나로 합치고, 사라진 노드는 링크 정리 대상으로 둔다.
- 같은 실패가 여러 노드에 반복되면 원인 노드에는 판단을 남기고 후속 노드에는 그 역할의 적용 조건만 남긴다.
- 교차 결과가 두 판단을 나란히 붙인 형태라면 더 약한 판단을 지우고 하나의 실행 문장으로 압축한다.
- 교차 결과가 핵심 사슬을 흐리면 새 규칙 추가보다 기존 문장의 압축이나 위치 이동을 고른다.
- 상위 후보 2개가 같은 이른 원인 노드를 가리키면 여러 변경으로 쪼개지 않고 가장 강한 한 문장 보정으로 합친다.
- 여러 개선을 고를 때는 각 개선의 역할을 원인 발견, 정보 추출, 생성 실행, 훅 연결, 평가, 탐색 중 하나로 먼저 나누고, 같은 판단이나 같은 역할의 후보는 병합하거나 하나만 남긴다.
- [[세대-후보-생성]]에서 묶은 역할 경계를 교차 중에 바꾸지 않고, 교차 결과가 새 역할을 만들면 이번 세대 묶음에서 빼거나 기존 역할 하나로 압축한다.
- 결합 뒤 한 노드가 길어지거나 유사 노드가 남아 역할 경계가 흐리면 결합 문장을 더 붙이지 않고 [[노드-경계-정리-방식]]으로 분리하거나 병합한다.

## 금지

- 강한 규칙 둘을 단순히 길게 합치지 않는다.
- 교차 결과가 소설 장면 예시를 포함하지 않는다.
- 결합 뒤 새 의무가 선택한 개선 각각의 역할 경계를 넘어 번지면 한 세대 묶음으로 채택하지 않는다.
