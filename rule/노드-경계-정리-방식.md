# 노드 경계 정리 방식

## 역할

이 방식은 너무 길거나 유사해진 규칙 노드를 한 파일 한 역할 원칙에 맞게 분리하거나 병합하는 변이 방식이다.
정리된 노드는 서로 겹치지 않고 전체 역할 범위를 빠짐없이 덮어야 한다.

## 적용 조건

다음 중 하나가 보이면 노드 분리 후보로 본다.

- 역할 경계는 [[세대-후보-생성]]과 같은 원인 발견, 정보 추출, 생성 실행, 훅 또는 연속성 연결, 평가, 탐색 기준으로 먼저 나눈다.
- 한 노드가 80줄을 넘거나 항목이 30개를 넘어 다음 실행에서 가장 이른 원인 판단을 찾기 어렵다.
- 한 노드 안에 입력 추출, 회차 실행, 훅 연결, 평가, 탐색처럼 서로 다른 역할이 섞여 있다.
- 같은 하위 역할의 규칙이 5개 이상 이어져 독립 노드로 빼는 편이 더 빠르게 참조된다.
- 새 규칙을 더 넣으면 기존 노드의 역할 문장보다 예외와 보정 문장이 더 길어진다.
- 같은 입력이나 판단이 둘 이상의 노드에서 같은 방식으로 처리되어 소유 경계가 흐려진다.

## 분리 절차

1. 먼저 중복 삭제, 병합, 축약으로 줄일 수 있는지 본다.
2. 줄인 뒤에도 길면 반복해서 쓰이는 하위 역할 하나를 고른다.
3. 분리 기준은 입력 종류, 생성 단계, 실패 원인, 판단 방식 중 하나만 고른다.
4. 새 노드들이 서로 겹치지 않고 원래 노드의 필요한 범위를 빠짐없이 덮는지 확인한다.
5. 새 노드 이름은 하위 역할을 드러내는 한국어 명사로 정한다.
6. 원래 노드에는 하위 역할의 요약, 새 노드 링크, 넘기는 조건만 남긴다.
7. 새 노드는 한 역할만 맡고 원래 문장을 그대로 복사하지 않고 실행 판단으로 재압축한다.
8. 새 노드와 원래 노드의 들어오는 링크와 나가는 링크를 함께 정리한다.
9. 링크를 바꿨다면 끊긴 위키 링크가 없는지 확인한 뒤 상태를 갱신한다.

## 병합 절차

- 두 노드가 같은 입력, 같은 판단, 같은 후속 노드를 다루며 역할 차이를 한 문장으로 말할 수 없으면 병합 후보로 본다.
- 병합 전 두 노드의 생성 역할, 평가 역할, 탐색 역할, 변이 역할이 섞이지 않는지 확인한다.
- 병합 노드는 더 이른 원인 판단을 가진 쪽을 기준으로 남기고, 다른 노드의 고유 판단만 실행 문장으로 압축해 옮긴다.
- 옮긴 뒤 남는 노드가 별도 역할을 잃으면 삭제 후보로 두고, 들어오는 링크를 병합 노드로 바꾼다.
- 병합해도 한 노드 한 역할 원칙을 지키지 못하면 병합하지 않고 중복 문장만 제거한다.

## 금지

- 줄 수만 맞추려고 같은 역할을 임의로 둘로 쪼개지 않는다.
- 비슷해 보인다는 이유만으로 입력 종류나 생성 단계가 다른 노드를 합치지 않는다.
- 하나의 입력이나 판단을 두 노드가 동시에 소유하게 만들지 않는다.
- 원래 노드의 필요한 판단 범위를 새 노드 어디에도 두지 않은 채 제거하지 않는다.
- 생성규칙, 평가기준, 교차 방식, 변이 방식을 한 노드에 섞지 않는다.
- 원래 노드와 새 노드에 같은 판단을 반복해서 읽기 비용을 늘리지 않는다.
- 새 노드가 소설 장면 예시나 고정 템플릿을 만들게 하지 않는다.
