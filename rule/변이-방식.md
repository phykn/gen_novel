# 변이 방식

## 역할

변이는 기존 규칙의 작은 결함을 바꿔 다음 세대에서 더 잘 작동하게 만드는 방식이다.

## 적용 조건

다음 중 하나가 보이면 변이를 적용한다.

- 규칙이 입력에서 추출해야 할 정보를 빠뜨린다.
- 규칙이 너무 추상적이라 실행 판단으로 이어지지 않는다.
- 후속 노드에서 반복해서 보정하는 실패의 더 이른 원인 노드가 보인다.
- 규칙이 장면 템플릿처럼 굳어져 다양한 입력에 약하다.
- 링크가 부족해 다음 실행에서 관련 규칙을 찾기 어렵다.
- 오래된 규칙이 현재 그래프 상태와 맞지 않는다.
- 같은 제한이 여러 노드에 반복되어 어느 노드의 판단인지 흐려진다.
- 노드가 길어져 한 파일 한 역할 원칙이 흐려지고 다음 실행에서 원인 판단을 찾기 어렵다.

## 변이 방법

변이는 선택한 약점 하나의 실패 가능성을 실제로 줄여야 한다.
1개 실질 보정만 고른 세대에서는 그 보정이 가장 이른 원인 노드 하나와 한 역할만 바꿔야 한다.
[[세대-후보-생성]]으로 여러 개선을 묶는 세대에서는 각 변이가 같은 핵심 실패를 줄이되 정보 추출, 생성 실행, 후속 연결, 평가, 탐색 중 하나의 역할만 맡아야 한다.
교차 뒤 변이가 필요해도 [[세대-후보-생성]]에서 정한 역할 경계를 넓히지 않고, 새 역할이 필요하면 다음 세대 후보로 남긴다.
같은 역할에 같은 판단을 반복하는 보정은 더 이른 원인 노드의 보정 하나로 합치고 별도 개선으로 세지 않는다.
작은 보정이라도 주인공 선택, 선택의 대가가 시험할 것, 다음 행동 압력 중 무엇을 더 실행 가능하게 하는지 분명해야 한다.

- 추출 대상 하나를 추가하거나 제거한다.
- 모호한 표현을 실행 가능한 판단 문장으로 바꾼다.
- 과하게 세부적인 장면 지시를 입력 기반 판단으로 바꾼다.
- 관련 노드 링크를 추가하거나 끊어진 링크를 고친다.
- 같은 의미를 가진 문장을 줄인다.
- 후속 노드의 반복 보정이 사라지도록 더 이른 원인 노드의 판단을 고친다.
- 더 이른 원인 노드가 고쳐졌다면 후속 노드의 같은 판단 문장은 역할 적용 조건만 남기고 줄인다.
- 반복 제한은 실행 판단에 가장 가까운 노드에 남기고, 다른 노드에서는 역할별 차이가 없으면 제거한다.
- 축약 뒤에도 노드가 길거나 유사 노드가 남으면 [[노드-경계-정리-방식]]으로 서로 겹치지 않게 분리하거나 병합하고 원래 노드에는 링크와 넘기는 조건만 남긴다.

## 금지

- 변이를 이유로 규칙을 장황하게 늘리지 않는다.
- 한 개선 항목 안에서 여러 목적을 동시에 바꾸지 않는다.
- 소설 원고나 장면 예시를 만들지 않는다.
- 맞춤법, 표현 통일, 상태 문구 변경만으로 한 세대 변이를 끝내지 않는다.
